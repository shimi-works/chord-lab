ChordLab

音楽理論ゼロでも、
作りながら学べる作曲アプリ。

ブラウザだけで動く、コード進行・メロディ・ドラムの打ち込みと、コード学習を1つにした単一HTMLアプリ。「知識を整理して“体験”に変える」という一貫した設計思想で作っています。

単一HTMLファイル Vanilla JS · ビルドなし Web Audio API 外部依存ほぼゼロ GitHub Pages
ライブデモを開く shimi-works.github.io/chord-lab

01 — 設計思想

「便利なツール」ではなく、
学習・創作の“体験”を設計する。

機能の多さより、初心者が最後まで1曲を完成させられることを軸に据えています。そのための判断が、以下の原則に一貫して現れています。

P1

理論を「見える化」する

コードを押すと構成音がピアノロール上で光る。コードの役割（トニック／サブドミナント／ドミナント）を色で示す。鍵盤図で転回形を可視化。抽象的な音楽理論を、目と耳で掴める形に翻訳しています。

P2

“完成”までの導線を用意する

条件をクリアすると次へ進める7ステップの作曲講座。コード→ベース→ドラム→メロディ→くり返し→仕上げの順で、読み進めるだけで1曲できあがる。初回起動時は「学ぶ／作る」を選ぶ導線に振り分けます。

P3

摩擦を極限まで減らす

インストール不要・アカウント不要・オフライン動作。単一HTMLで外部依存を最小化し、URLを開けば誰でもすぐ触れる。作品を「見てもらう」までの距離をゼロに近づけています。

P4

“おもちゃ”で終わらせない

MIDI／WAVの書き出しで、作ったものを本物のDAW（Cubase等）や音声ファイルとして持ち出せる。学習アプリでありながら、実制作フローの入口にもなるよう設計しています。

P5

依存を増やさないことを機能と考える

コード提案も進行解析もメロディ生成も、外部AIを使わずルールベースで実装。これによりオフライン動作・鍵不要・軽量という強みを保ったまま、「かしこさ」を足しています。

02 — アーキテクチャ

構成はシンプルに、音まわりは正確に。

フレームワークもビルドも使わない、素のHTML/CSS/JS 1ファイル。状態は単一の S オブジェクトに集約し、UIはそこから再描画する一方向の流れにしています。永続化と共有、取り消しをすべて同じスナップショット表現で扱えるのが利点です。

  • State

    単一 S オブジェクト

    コード進行・4トラックのノート・ミキサー・セクション等をまとめて保持。

  • 永続化

    localStorage

    自動保存＋名前付きマイソング。端末内に残る。

  • 共有

    URLハッシュ

    曲データを #song= に埋め込み、リンクだけで同じ曲を再現。

  • Undo

    JSONスナップショット

    操作ごとの状態を32手ぶん保持し、取り消し／やり直し。

03 — 技術的ハイライト

面白かった／手応えのあった実装。

AUDIO

デュアル音源エンジン

soundfont-player でGM音源（グランドピアノ等）の実サンプルを鳴らしつつ、読み込み失敗時はオシレーター合成音へ自動フォールバック。ネットワークに関係なく“必ず鳴る”ことを保証。

EXPORT · MIDI

SMFをバイト列で手書き

ライブラリを使わず Standard MIDI File（format 1）を生成。可変長数値(VLQ)・テンポ／拍子メタ・楽器別トラック・ドラムのGMマッピングまで、仕様どおりのバイナリを組み立てる。

EXPORT · WAV

オフラインで一括レンダリング

OfflineAudioContext に内蔵シンセの発音を再構成し、ミキサー設定を反映して一括レンダー。得たバッファを16bit PCMの WAVヘッダごとエンコードして書き出す。

THEORY · NO-AI

音楽理論エンジン（ルールベース）

ダイアトニック／機能和声、定番進行の照合（回転・反復を許容）、メロディ採点、自動生成、転回形。外部AIに頼らず、依存ゼロで“かしこさ”を実装。

UI · ROLL

マルチトラック・ピアノロール

4レーンの座標計算、"midi:step"→長さ の疎マップでノートを表現。範囲選択・一括リサイズ・ハサミ／のり・ペン（スマホ対応）まで自作。

PORTABILITY

単一ファイルという制約

1つのHTMLに全部入り。外部依存はCDNのsoundfontのみで、それが無くても動く。壊れにくく・配りやすく・長持ちする構成を意図的に選択。

04 — スポットライト

差別化の核＝音楽理論エンジン

「機能はあるが何をすればいいか分からない」無料ツールが多い中で、Chord Lab は作りながら理解が進むことを狙っています。その心臓部が、AIを使わないルールベースの理論エンジンです。

ANALYZE

進行解析

並べたコードが王道／カノン／小室／ツーファイブ等の定番かを判定し、機能の流れ（T→S→D）と印象を言語化。

SCORE

メロディ採点

コードトーン率・順次/跳躍・キー適合を数値化し、改善のヒントを提示。「なぜ良い／外れるか」を可視化。

GENERATE

自動メロディ生成

強拍にコードトーン、弱拍は順次進行——入門の定石をコード化し、進行に沿ったメロディを生成。

なぜルールベースか。 外部AIのAPIを入れれば一見“賢く”なりますが、その瞬間に「オフラインで動く・鍵がいらない・軽い」という本アプリの強みを1つ失います。教育的な説明可能性の面でも、理論を明示的にコード化する方が筋が良いと判断しました。

trade-off = 依存性 vs. 賢さ  →  自己完結を優先し、賢さは理論の明示実装で補う

05 — 機能マップ

作る・学ぶ・持ち出すを一枚に。

作る

  • コード進行（ダイアトニック／プリセット）
  • 4トラック・ピアノロール
  • ドラムパターン貼り付け
  • 転回形・コード提案
  • 自動メロディ生成

整える

  • ミキサー（音量/ミュート/ソロ）
  • 移調・クオンタイズ
  • ループ・セクションマーカー
  • コピー／複製・一括リサイズ
  • Undo / Redo（32手）

学ぶ

  • 7ステップ作曲講座
  • コード練習（鍵盤図＋クイズ）
  • 楽曲アナライザー
  • 用語ミニ辞典
  • 使い方リファレンス

持ち出す

  • MIDI 書き出し（.mid）
  • WAV 書き出し（.wav）
  • 共有リンク（URL）
  • マイソング保存
  • U-FRET 読み込み

06 — 開発プロセス

“動いた”ではなく“動くと確かめた”を出す。

単一ファイルで機能が密集するため、リグレッションが起きやすい。そこで公開前に必ず2段の自動検証を通す運用にしています。UIの見た目だけでなく、実際の操作をプログラムで再現して挙動を確かめてからデプロイします。

小さくコミットし、GitHub Pages へ即デプロイ。公開版で最終確認する反復サイクルで作っています。

  • 静的検査

    構文・重複宣言チェック

    node --check でパースエラーや二重宣言を検出。

  • 実行検証

    ヘッドレスブラウザ

    ランタイムエラーを捕捉し、PointerEvent/クリックを自動発火して機能を実測。

  • デプロイ

    公開版で確認

    反映後、ライブURLで実際に触れて最終チェック。
